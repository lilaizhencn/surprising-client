# Telegram 登录与移动端页面改版验收

本特性在 `feature/telegram-okx` 分支实施。整体要求全部通过前不合并 `main`，也不把自动化测试通过视作全部完成。

## Telegram 登录

- 登录及注册都提供 Telegram 按钮；系统浏览器授权，领取凭据只放内存，关闭页面后不接受迟到的会话。
- 沿用 AppState 的登录会话、私有数据加载、持久化和现有二次验证，登录后优先显示 `displayName`。无密码、无邮箱账户可以解析及持久化。
- 后端接口与配置参见后端 `docs/telegram-login.md`。未配置时按钮禁用；授权失败、取消或过期不写入会话。
- 2026-10-20：完整 `flutter test` 376 项通过，10 项依赖真实交易环境的测试按已有条件跳过；`flutter analyze` 无问题。后续 UI 变更后需要重新执行相应验收。
- 真实 Telegram 授权尚待完成；Android/iOS 原生运行证据见下文。

## 当前分支验证进度（仍未满足合并条件）

- 2026-10-20：最新完整 Flutter 测试 438 项通过，10 项既有在线环境测试跳过。首页/行情、资产筛选、分步充值、提现选币/选网络及划转数字键盘已接入现有状态与接口。
- 划转页面最大数量使用币种目录的真实精度及账户最小单位计算，320/392 像素深浅主题测试覆盖 6 位精度、余额上限和待确认锁定；充值测试覆盖旧网络迟到响应和账户退出；提现从独立网络规则读取网络，资金余额不按链复制。
- Android 模拟器已验证真实 WebView 中的 TradingView 5.2.1、原生二维码图片解码和系统 `SECURE` 标记；系统截图确认保护时黑屏、退出后恢复。截图回调须在场景挂载时执行：`scripts/native-redesign-qa.py` 使用文件握手采集系统截图，避免 Flutter 截图遗漏 WebView。
- iOS 模拟器已构建、启动并执行首页、行情、图表及保护路径；插件明确不支持在 iOS 模拟器分析二维码图片，该限制在原生报告中单独记录，不能当作 iOS 实机扫码验证。
- iOS 的 UIKit/Flutter 截图已被遮蔽，但模拟器 `simctl` 系统截图仍显示受保护内容；iOS 防截屏未标记通过。同类 secure-text-layer 实现明确说明[模拟器与实机渲染不同](https://github.com/ckdash-git/ScreenShield#simulator-vs-device)，本应用仍需真机验收，不能据此承诺实机保护效果。
- Android/iOS 最新版本均已运行 17 个原生场景并在页面挂载时采集系统截图；提现保护在 Android 已验证，在 iOS 模拟器未通过。真实 Telegram 授权、今日收益后端，以及扫码相册、保存/分享系统界面的进一步交互验证仍待完成。当前收益缺少可信数据时显示 `—`，不填模拟数字。

- 划转已按用户持久化不可变原请求，提交前必须保存成功；重启、超时、404 和安全验证均只允许继续原幂等键，确认完成后必须成功清除安全存储才解锁。验证码不落盘。
- 资金余额保留服务端精确小数字符串；提现“全部”按网络精度向下截取，配置中的科学计数法手续费按整数运算规范化。产品估值使用币种真实精度，缺失精度不猜测。
- 扫码启动、停止及销毁已串行化，覆盖权限请求未结束就关闭页面、左右切页、外部二维码拒绝和账户切换后的迟到响应。旧并发实现已在回归测试中复现相机未停止。
- 图表使用与 Web 相同的周期补齐和 120 根窗口，补齐柱仅沿用上一收盘价、成交量为零；公开行情数据才可进入 WebView。
- 本轮完整证据、截图哈希和未验收项见 [验收记录](validation/telegram-mobile-redesign-20261020.json)。当前仅提交特性分支，不合并主分支。

- 无密码账户安全设置已接入服务端近期主认证上下文：新绑定要求目的邮箱/手机号及验证码，不展示无法输入的密码框；超过 5 分钟须重新登录，刷新令牌不延长认证时限。账户切换后的迟到响应不可继续设置。4 项回归测试通过，完整 438 项测试及 analyze 通过；见 [独立验收记录](validation/passwordless-security-20261020.json)。

## 移动端整体要求（尚未全部实现）

- 首页：对照桌面 `okx_index.jpg`，交易所标题、通知和头像、共享搜索框、扫码入口、总资产和今日收益、链上充币和 C2C 按钮、公告、包含图标/币对/交易量/最新价/法币/涨跌幅的行情列表。无 Web3 钱包。
- 扫码：扫一扫与我的二维码支持点击和左右滑动，能识别平台其他用户。
- 底部：仅按参考图调整中央交易按钮，其余导航保持原产品能力。
- 行情：产品线置顶、移除冗余标题、与首页共用搜索组件且无扫码、六条产品线隔离、点币对进入走势页。K 线与 Web 的 TradingView Lightweight Charts 保持一致。
- 资产：对照 `okx_asset.jpg`；资金与交易账户、币种数量/价值、充币/提币/划转动作，使用服务端真实资产。
- 充值：按 `充值 5.jpg` → `充值 4.jpg` → `充值 3.jpg` → `充值 2.jpg` → `充值 1.jpg` 的入口、资产列表、网络、二维码地址与菜单顺序实现；保留 Memo、安全提示、复制、保存/分享和记录。
- 提现：类似分步流程，币种列表显示每币可用余额；敏感页面启用原生截图保护，保留费用、精度、二次验证与幂等保护。
- 划转：对照 `划转.jpg`，账户互换、币种、数量/最大、可用余额、数字键盘；保持账户类型隔离、精确数量与未知结果防重复提交。
- 在小屏、深浅主题、Android/iOS 上验证真实页面、交互、网络失败、账户切换及产品切换。全部功能通过后才提交最终验证记录并合并各仓库主分支。
